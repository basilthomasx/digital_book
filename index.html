Chapter 1

The generic process model

A software process is a collection of activities, actions and tasks performed to create a work product. Pressman describes a generic process model built around five framework activities that apply to almost every project, large or small [1].

Five framework activities

Tap an activity to see what happens in it.

Actions, task sets and umbrella activities

Each framework activity contains one or more actions (for example, elicitation inside communication), and each action has a task set: the work tasks, work products, quality assurance points and project milestones needed for it. The task set is adapted to the size and risk of the project [1].

Umbrella activities run across the whole process. They include project tracking and control, risk management, software quality assurance, technical reviews, measurement and configuration management [1].

The process flow can be linear, iterative, evolutionary or parallel. Choosing among these flows is what separates the different process models [1].

Prescriptive process models

Prescriptive models define a set of activities and their order, and each one suits a different kind of project [1][2].

ModelIdeaGood when
WaterfallLinear: communication, planning, modeling, construction, deploymentRequirements are fixed and well understood
IncrementalDeliver working increments, core firstEarly delivery matters, staff is limited
PrototypingBuild a quick mock-up, refine with feedbackRequirements are vague
SpiralEvolutionary cycles driven by risk analysisThe project is large and risky

Chapter 3

RAD, DevOps and Scrum

Specialized and agile approaches trade some ceremony for speed and feedback [1][2].

RADA very short incremental cycle, often 60 to 90 days, using component-based construction and parallel teams. It needs modular systems and enough people [1].
DevOpsJoins development and operations so that building, integrating, deploying and collecting feedback form a continuous loop [1][4].
ScrumAn agile framework that delivers work in short timeboxed sprints, with three roles: Product Owner, Scrum Master and Developers [3].

Scrum follows the values of the Agile Manifesto, such as working software over comprehensive documentation and responding to change over following a plan [5].

Chapter 4

Summary and references

Every process, however different it looks, rests on the same five framework activities and the same umbrella activities. Prescriptive models fix the order of work, so they suit stable requirements. RAD, DevOps and Scrum shorten the cycle and bring the customer and operations into the loop. The skill is matching the model to the project.

Quick check. A client cannot describe the requirements clearly, but can react to something they can see and use. Which model fits best?
